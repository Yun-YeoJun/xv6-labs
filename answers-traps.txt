Q1. 함수 인자를 저장하는 레지스터는 무엇인가? 예를 들어, main 함수에서 printf를 호출할 때 13이라는 값을 저장하는 레지스터는 무엇인가?

A. x10~11 레지스터, 즉 a0~1 레지스터에는 함수의 매개변수나 반환 값이 저장된다. x12~17 레지스터, 즉 a2~7 레지스터에도 함수의 매개변수가 저장된다.
함수의 인자를 저장하는 레지스터는 x10--17이다. ABI Name으로는 a0--7 레지스터이다.

"user/call.asm" 파일에서 main 함수에 대한 어셈블리 코드를 살펴보면 다음과 같다:

```
000000000000001c <main>:

void main(void) {
  1c:	1141                	addi	sp,sp,-16
  1e:	e406                	sd	ra,8(sp)
  20:	e022                	sd	s0,0(sp)
  22:	0800                	addi	s0,sp,16
  printf("%d %d\n", f(8)+1, 13);
  24:	4635                	li	a2,13
  26:	45b1                	li	a1,12
  28:	00001517          	auipc	a0,0x1
  2c:	84850513          	addi	a0,a0,-1976 # 870 <malloc+0x100>
  30:	68c000ef          	jal	6bc <printf>
  exit(0);
  34:	4501                	li	a0,0
  36:	26e000ef          	jal	2a4 <exit>
```

0x24 라인을 살펴보면 printf를 호출할 때 13이라는 값을 a2 레지스터에 저장하는 것을 볼 수 있다.

Q2. main 함수의 어셈블리 코드에서 함수 f의 호출은 어디에 있는가? 함수 g의 호출은 어디에 있는가? (힌트: 컴파일러가 함수를 인라인 처리할 수 있다.)

A. "user/call.asm" 파일을 살펴보자. 어셈블리 코드를 보면 함수를 호출하지 않고 컴파일러가 인라인 처리한 것을 확인할 수 있다.

```
000000000000000e <f>:

int f(int x) {
   e:	1141                	addi	sp,sp,-16
  10:	e422                	sd	s0,8(sp)
  12:	0800                	addi	s0,sp,16
  return g(x);
}
  14:	250d                	addiw	a0,a0,3
  16:	6422                	ld	s0,8(sp)
  18:	0141                	addi	sp,sp,16
  1a:	8082                	ret

000000000000001c <main>:

void main(void) {
  1c:	1141                	addi	sp,sp,-16
  1e:	e406                	sd	ra,8(sp)
  20:	e022                	sd	s0,0(sp)
  22:	0800                	addi	s0,sp,16
  printf("%d %d\n", f(8)+1, 13);
  24:	4635                	li	a2,13
  26:	45b1                	li	a1,12
  28:	00001517          	auipc	a0,0x1
  2c:	84850513          	addi	a0,a0,-1976 # 870 <malloc+0x100>
  30:	68c000ef          	jal	6bc <printf>

  34:	4501                	li	a0,0
```

0x14 라인을 보면 "addiw a0,a0,3" 명령이 있다. 원래는 함수 g를 호출해야 하지만, 바로 a0에 a0+3을 저장하고 있다.
마찬가지로 0x26 라인을 보면 li a1,12가 실행된다.
이는 컴파일러가 함수 호출 대신 상수를 바로 레지스터에 넣는 작업으로 바꾼 것이다.
컴파일러의 인라인 처리가 없었다면 f(8)+1을 계산해서 12라는 값을 얻었어야 한다.

Q5. 다음 코드를 실행하라. 출력 결과는 무엇인가? 바이트를 문자로 매핑하는 ASCII 표를 참고하라.
출력은 RISC-V가 리틀 엔디안이라는 사실에 달려 있다.
만약 RISC-V가 빅 엔디안이라면 동일한 출력을 얻기 위해 i를 어떤 값으로 설정해야 하는가?
57616을 다른 값으로 변경해야 할까? 리틀 엔디안과 빅 엔디안에 대한 설명과 좀 더 기발한 설명을 참고하라.
```
unsigned int i = 0x00646c72;
printf("H%x Wo%s", 57616, (char *) &i);
```

A. 주어진 코드를 xv6에서 실행하면 "HE110 World"가 출력된다. 여기서 "E110"은 57616의 16진수 표현이고, "rld"는 "(char *) \&i" 의 결과이다.
RISC-V가 빅 엔디안 방식이라도 57616의 16진수 표현은 바뀌지 않기 때문에 같은 결과를 얻기 위해 57616을 다른 숫자로 대체할 필요는 없다.
리틀 엔디안, 빅 엔디안 방식은 메모리와 관련이 있기 때문에 (char *) \&i 의 출력 결과는 바뀐다.
i 에는 0x00646c72 가 저장된다.
리틀 엔디안에서는 이를 "0x72", "0x6c", "0x64", "0x00" 순서로 인식한다.
이는 각각 "r", "l", "d", "NUL"을 의미한다.
(char *) \&i 의 출력 결과가 “rld”인 것이다.
한편 빅 엔디안에서는 0x00646c72를 "0x00", "0x64", "0x6c", "0x72" 순서로 인식한다.
"0x00" 은 문자열의 끝을 의미하기 때문에 빅 엔디안일 경우 전체 문자열은 “HE110 Wo”가 출력된다.
빅 엔디안의 경우, 리틀 엔디안과 동일한 출력을 얻기 위해서는 {i}를 0x726c6400 으로 설정해야 한다.

Q6. 다음 코드에서 "y=" 뒤에 출력될 값은 무엇인가? (참고: 답은 특정 값이 아니다.) 왜 이런 현상이 발생하는가?
```
printf("x=%d y=%d", 3);
```

A. 위 코드를 포함하는 c 파일을 컴파일하면 경고가 뜬다.
printf 함수에 int 형 매개변수 하나가 부족하다는 의미이다.
별다른 컴파일 옵션을 지정해주지 않으면 경고만 뜨고 컴파일이 되기는 한다.
컴파일을 통해 만들어진 실행 파일을 실행해보자.
"y=" 뒤에 쓰레기 값이 출력된다.
printf의 어셈블리 코드를 보면 초반에 a1부터 a7까지의 레지스터에 저장된 값을 s0 + n 위치에 저장한다.
즉, 주어진 매개변수 개수와 관계없이 a0를 제외하고 함수 매개변수 레지스터를 모두 읽는다.
호출하는 쪽에서 매개변수를 지정해줬다면 해당 매개변수 레지스터에 올바른 값이 들어가 있을 것이다.
하지만 매개변수를 지정해주지 않았다면 매개변수 레지스터에는 쓰레기 값이 들어가 있을 것이다.
매개변수 2개를 사용하도록 하고 매개변수를 1개만 줬기 때문에 "y=" 뒤에는 레지스터에 담겨 있던 쓰레기 값이 출력된다.
